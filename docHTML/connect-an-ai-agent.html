MMSBUILD · Operator guide

Give an AI a keycard to a client site

It can write pages, draft posts and upload images. You decide exactly what it may touch.

You'll work here https://siteagent.tailbbb0d2.ts.net/operator/mcp

What you're actually handing over

A keycard. Like a real one, it opens some doors and not others — and you choose which when you make it. If the AI does something you don't like, you cancel the card and it stops working on its very next request.

Two things go to whoever runs the AI:

ThingWhat it isExample
AddressA web link, one per client sitehttps://…/mcp/acme-dental
KeyA long password that decides what the AI may dommsmcp_8Kd93jRmQp…

That's the entire connection. Open the console link above and you'll find three sections: Create a key, Keys, and Endpoint directory.

1

Turn the site on for AI accessonce per site

Scroll to Endpoint directory at the bottom. Every client site is listed:

SiteBridgeKeys
acme-dentalnot installed0Install bridge
bright-cafeinstalled2Reinstall

Press Install bridge on the site you want. Wait a few seconds — the Bridge column changes to installed. You only do this once per site, ever.

What it does: switches on the part that lets an AI build page layouts properly, using the CMS's own tools instead of editing from outside. Without it the AI can still handle images and site-wide styling, but not pages or posts.

"site not running" means that client's site is stopped. Start it from the Tenants page, then come back.

2

Create a key

Scroll to Create a key at the top.

Site — pick the client, e.g. acme-dental. The key works on this site and no other.

Label — a name so you recognise it later, e.g. blog-writer. Just for you.

Tables — blank allows everything. Type posts and the AI can only touch blog posts, never the homepage.

Expires in — blank means never. 90 means the key dies after 90 days.

Then tick the permissions — the part that matters:

TickThe AI can
readLook at pages, posts and content. Change nothing
createMake new pages and blog posts — as drafts
editChange existing content and page layouts
deleteMove things to Trash (a person can restore them)
publishPush work live to the real website
tables.manageCreate new content collections
media.readBrowse the image library
media.writeUpload and edit images
media.deleteMove images to Trash
design.editChange site-wide colours, fonts and styles

Press Create key.

Copy it now

A green box appears with your key. This is the only time it is ever shown. Only a fingerprint is stored, so nobody can read it back later — not even you.

Four copy buttons: Copy key (the password alone), Copy endpoint (the address alone), Copy command (a ready-to-paste setup line for Claude Code), and Copy both (address and key, for other tools).

Lost it? Revoke the key and make a new one. Ten seconds.

Group B · Only runs a command

These can't call a URL themselves. mcp-remote bridges the gap — it runs locally and forwards to the endpoint. It comes from npm, so Node must be installed.

Claude Desktop

Settings → Developer → Edit Config, then:

{
  "mcpServers": {
    "mms-cms": {
      "command": "npx",
      "args": [
        "-y", "mcp-remote",
        "https://siteagent.tailbbb0d2.ts.net/mcp/acme-dental",
        "--header", "Authorization:${AUTH}"
      ],
      "env": { "AUTH": "Bearer mmsmcp_8Kd93jRmQp2xVn..." }
    }
  }
}

Restart Claude Desktop. The tools appear under the tools icon in the message box.

Why the key sits in env, not args: the header value contains a space, which breaks argument parsing. Putting it in env and referencing it as ${AUTH} is the standard workaround — and it applies to every example in this group.

Codex CLI

Edit ~/.codex/config.toml:

[mcp_servers.mms-cms]
command = "npx"
args = ["-y", "mcp-remote", "https://siteagent.tailbbb0d2.ts.net/mcp/acme-dental", "--header", "Authorization:${AUTH}"]
env = { AUTH = "Bearer mmsmcp_8Kd93jRmQp2xVn..." }

Any other command-only tool

Same shape everywhere — a command, its arguments, and one environment variable:

command:  npx
args:     -y  mcp-remote  https://siteagent.tailbbb0d2.ts.net/mcp/acme-dental  --header  Authorization:${AUTH}
env:      AUTH = Bearer mmsmcp_8Kd93jRmQp2xVn...

Group C · Web assistants — not supported

claude.ai and ChatGPT custom connectors run on the provider's servers and sign in with OAuth. They have no field for a custom header, so they cannot send the key.

Use a desktop or CLI tool from the groups above instead. Anyone can connect their own copy of Claude Desktop or Claude Code with the key you give them.

Check the connection

Any tool, any language — this asks the endpoint what it can do:

curl -X POST https://siteagent.tailbbb0d2.ts.net/mcp/acme-dental \
  -H "Authorization: Bearer mmsmcp_8Kd93jRmQp2xVn..." \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

A working key returns a long list of tools. A bad or revoked key returns "Invalid, revoked, or expired agent key".

What it looks like in use

A key with read, create, edit — but not publish:

Staff

Write a blog post about our new teeth whitening service.

Claude

I've looked at your existing posts to match the style. I've created "Professional Teeth Whitening — What to Expect", about 600 words, saved as a draft. It's not live yet.

Staff

Add a photo to it.

Claude

Uploaded whitening-chair.jpg and set it as the header image. I've added alt text for accessibility: "Dental hygienist preparing a whitening treatment".

Staff

Great, publish it.

Claude

I don't have permission to publish. The post is ready in your CMS as a draft — someone with publishing access can review and publish it.

The AI did the work. A person still decides what goes live. That's what leaving publish unticked buys you.

The same job with publish ticked

Staff

Write a post about teeth whitening and put it live.

Claude

Published "Professional Teeth Whitening — What to Expect". It's live at /blog/professional-teeth-whitening.

No human check. Use this only for content you're happy going out unreviewed.

What the AI can do

Looking — list the site's content types; read any page, post or layout; search; see what's live versus still a draft.

Writing — create pages and posts; edit text and fields; build layouts by adding, moving, duplicating and removing sections; style each section, including how it looks on mobile; move content between collections; delete to Trash.

Images — browse the library; upload; set alt text, captions and tags; organise into folders; replace an image everywhere it's used; delete to Trash and restore.

Site-wide design — read and change colours, fonts, spacing rules and breakpoints.

Going live — publish one item, schedule it for later, or refresh every published page after a site-wide change.

What it can never do

Touch users, roles or logins.No such action exists. Even a key with every box ticked cannot create an account, change permissions, or lock anyone out.
Reach another client's site.A key is bound to one site. Pointed anywhere else, it's rejected.
Delete anything permanently.Deletes go to Trash, and a person can restore them.

Managing keys

The Keys section lists every key: label, site, permissions, tables, last used, status.

Revoke stops a key working on its very next request. Use it when the work is finished, someone leaves the project, a key may have leaked, or the AI does something unexpected.

There's no undo, and that's deliberate — make a new key instead.

Last used tells you whether a key is still in service. Anything idle for months should probably be revoked.

When something doesn't work

What you seeWhat to do
"Invalid, revoked, or expired agent key"Wrong key, revoked, or past expiry. Also check it's for this site.
"This agent key is not valid for that site"Right key, wrong address. Match the site name at the end of the URL.
The AI says a tool isn't availableThat permission isn't ticked. Make a new key — keys can't be edited, so their power can never quietly grow.
"Table not found" when creating contentThe bridge isn't switched on for that site. Endpoint directory → Install bridge.
Images work but pages don'tSame cause — the bridge isn't switched on.
Connection refused / nothing respondsThat client's site is stopped, or the site name in the address is misspelled.

Good habits

  • Start without publish. Let the AI draft for a week. Read what it produces. Add publishing once you trust it.
  • One key per job. You can then revoke one without disrupting the rest, and the activity log shows who did what.
  • Use table limits. A blog-writing AI has no business touching the homepage — set Tables to posts.
  • Set an expiry on anything temporary. A one-month campaign key should expire in 30 days.
  • Treat a key like a password. Anyone holding it has the access it carries. Don't email it or paste it into a group chat — and keep the console link itself to people who should be handing out access.
