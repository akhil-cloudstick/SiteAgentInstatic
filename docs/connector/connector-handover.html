02

Why the same port

You were right to ask. Tailscale Funnel permits only 443, 8443 and 10000 — three ports, total. Port 443 is the Operator gateway that already fronts the operator console, every tenant's OpenDesign and every tenant's Instatic; 10000 is the tenant test funnel. Giving the connector its own funnel would have spent the last spare port on a service that does not need its own origin.

So the connector now sits behind the same gateway on a path, exactly like /design does. I added the route to the control plane rather than opening a second funnel.

PathGoes to
/operator/*Operator console
/design/*Shared OpenDesign build + the session tenant's daemon
/connector-mcpConnector MCP — new
everything elseThe session tenant's Instatic
03

What you start, once

Two processes. The connector must be listening before Operator proxies to it, or the gateway returns a 502 that reads like the backend is down.

# PowerShell. Note $env: — `export` is bash and will error here.

# 1 · generate a token (keep it — this exact value goes to the client)
bun -e "console.log(crypto.randomUUID().replaceAll('-','')+crypto.randomUUID().replaceAll('-',''))"

# 2 · start the connector MCP server, and LEAVE THIS WINDOW OPEN
cd s:\SiteAgentHub\Connector
$env:MMS_CONNECTOR_MCP_TOKEN = "<the token>"
$env:MMS_CONNECTOR_ALLOWED_ORIGINS = "https://siteagent.tailbbb0d2.ts.net"
bun src/main.ts serve --port 8787

# 3 · in a SECOND window, restart Operator so it picks up the route
cd s:\SiteAgentHub\Operator
npm run dev

Two windows, because both processes must stay running. On success the connector prints a short banner — listening address, endpoint, auth source, allowed origins — and then the prompt does not come back. That is correct: it is serving. Do not close the window or press Ctrl-C.

If no banner appears, it did not start. The usual cause is the port already being held by an earlier run; the error says so explicitly.

Confirm it before you send anything:

# curl.exe, not curl — PowerShell aliases bare `curl` to Invoke-WebRequest
curl.exe https://siteagent.tailbbb0d2.ts.net/connector-mcp/health
# {"ok":true,"service":"mms-connector-mcp"}
If that 502sThe connector is not listening on 8787 — the gateway found the route, dialled it, and nothing answered. Start it and retry. Operator does not launch it for you, and it dies when its window closes.
04

What you send the client

Two values. No repo access, no VPN, no tailnet membership, and no credentials for any CMS.

URL:   https://siteagent.tailbbb0d2.ts.net/connector-mcp
Token: <the token from step 1>

They run one command:

claude mcp add --transport http mms-connector \
  https://siteagent.tailbbb0d2.ts.net/connector-mcp \
  --header "Authorization: Bearer <token>"

Or paste this into any MCP client that reads JSON config:

{
  "mcpServers": {
    "mms-connector": {
      "type": "http",
      "url": "https://siteagent.tailbbb0d2.ts.net/connector-mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}

07

A worked example

Creating a page on globalnettech, taking it live, then removing it again. Plain requests — the assistant picks the tools.

1 "Connect to akhil"
   → session opens against globalnettech

2 "Create a draft page called Workstation Buying Guide"
   → created as DRAFT. Not public yet — nothing has changed on the live site.

3 "Show me that page"
   → full record back, so the content can be checked before it goes anywhere

4 "Change the title to Workstation Buying Guide 2026"
   → edits the draft. A published page would still show the OLD text at this
     point: an edit lands on the draft until it is published again.

5 "Publish it"
   → LIVE IMMEDIATELY on globalnettech

6 "Unpublish it"
   → route retracted, content kept. Reversible.

7 "Delete it"
   → gone permanently. No undo, no trash.

Steps 6 and 7 are not the same thing, and the difference matters. Unpublish takes a page off the site and keeps it. Delete destroys it. When the goal is "get this off the site", unpublish is almost always the right one.

The same sequence works on lovedale by saying client-b instead.

08

Limits worth knowing

Two real ones, and one that is deliberate.

Publishing is immediate and has no version rollback. A published row goes live at once, and unpublishing later retracts the route without restoring earlier content. There is no "revert to yesterday". Treat publish as the committing step it is.

Bulk import needs a bundle, and the tool that generates one from an existing website is not built yet. So connector_import_draft works, but only with a bundle someone already has — it is not yet a way to migrate a site in.

Destructive bulk replace is not exposed. The strategy that wipes a site before reinserting is refused through this interface by design; it belongs in a deliberate, supervised run, not a conversational request.

Everything is loggedEvery action — including every refusal — is written to the activity log with its time, the caller, the tool and the outcome. Deletions and publishes are tagged so they can be found at a glance.
09

Security

  • Refuses to start without a tokenMissing or under 32 characters aborts before the port opens, rather than starting and rejecting everything — which looks like a network fault.
  • Constant-time compareA wrong token cannot be recovered by timing the response.
  • Origin before authA bad Origin is rejected 403 before the token is ever compared.
  • Loopback onlyThe connector binds 127.0.0.1. Only the gateway can reach it.
  • No CMS credentialsThis process holds no session for any Instatic instance.
  • Turn it off instantlyCONNECTOR_MCP=0 and restart Operator — the route disappears.
