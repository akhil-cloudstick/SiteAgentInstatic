Documentation

MMS Connector

A content connector for MMS-CMS. Connect it to an AI assistant and it becomes a set of tools for reading, creating, editing, publishing and removing content across sites — in plain language.

Full CRUD + publish 2 configured One command
01

What it is

The connector exposes a CMS through the Model Context Protocol — an open standard for giving AI assistants access to tools. The assistant calls the tools; the work happens on the server.

There is nothing to install and nothing to keep updated. Two values are needed: an endpoint URL and an access token.

Once connected, content work happens conversationally. Rather than clicking through an admin interface, you describe what you want — list the recent posts, draft a page, change a title, publish it — and the assistant carries it out.

02

Connecting

For Claude Code, one command:

claude mcp add --transport http mms-connector \
  https://siteagent.tailbbb0d2.ts.net/connector-mcp \
  --header "Authorization: Bearer <token>"

For any other MCP-capable client, add this to its configuration:

{
  "mcpServers": {
    "mms-connector": {
      "type": "http",
      "url": "https://siteagent.tailbbb0d2.ts.net/connector-mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}

Restart the client afterwards. The tools then appear in its tool list, each prefixed connector_.

The endpoint is public and safe to keep in this document. The token is a credential and is issued separately — treat it like a password.

03

The two sites

Both sites are reachable through the one connection. Each runs its own CMS, and the connector keeps a separate session for each — so work on one never touches the other.

NameSiteContent
akhilglobalnettechWorkstation and laptop articles
client-blovedaleTravel blog — Kodaikanal and similar

The name goes in the request: "connect to akhil", "list the posts in client-b". With two configured, a tool called without a name refuses rather than guessing — the check that stops a page being published to the wrong site.

05

Setting up a collection

The sequence people actually run, and the one where a skipped step fails silently.

1 "Connect to akhil, then step up"

2 "Create a collection called Blog at /blog"
   → a routed collection. Entries will have their own URLs.

3 "Create the entry template for blog"
   → DO NOT SKIP. Without a template, every entry URL returns 404 —
     the rows exist and are published, but nothing renders them.

4 "Add SEO fields to the blog collection"
   → canonical, Open Graph, JSON-LD. Not in the stock schema.

5 "Import this bundle as draft"
   → content lands, still not public

6 "Publish the site"
   → the template takes effect and entry URLs resolve

Step 3 is the one that catches people. A collection without a template looks completely healthy from the CMS — correct rows, published status, no errors — and returns 404 for every entry.

06

Everyday example

1 "Connect to akhil"
2 "Create a draft page called Workstation Buying Guide"
   → created as DRAFT. Nothing has changed on the live site.
3 "Show me that page"
4 "Change the title to Workstation Buying Guide 2026"
   → edits the draft. A published page still shows the OLD text
     until it is published again.
5 "Publish it"          → LIVE
6 "Unpublish it"        → route retracted, content kept
7 "Delete it"           → gone permanently

Steps 6 and 7 are not the same thing. Unpublish takes a page off the site and keeps it. Delete destroys it. When the goal is "get this off the site", unpublish is almost always the right one.

07

Publishing goes public

Worth knowing before the first publish

A full-site publish can reach the public internet, not just the CMS.

Publishing triggers a deployment to public hosting. The publish itself reports success as soon as the CMS is updated, and the deployment continues separately — so a clean publish response does not confirm the deployment worked, and does not tell you if it failed.

Publishing has no version rollback. Unpublishing retracts a route; it does not restore earlier content. Treat publish as the committing step it is, and check connector_publish_status before and after.

For bulk work, publish once at the end rather than per item — each publish is a separate deployment of an intermediate state.

08

Reading large sites

Listing returns summaries by default — id, slug, status, title and dates. A single page can carry several megabytes of layout, so a few hundred of them is more than one response can carry.

When you need the full content of a page, ask for one: "show me that page in full". When you genuinely need bodies for several, say so explicitly and keep the number small.

Listing is paginated and reports a total, so "show me the next 25" works through a site of any size.

09

Limits worth knowing

Publishing is immediate and cannot be rolled back to a previous version. Unpublishing retracts the route without restoring earlier content.

Deletion has no trash. There is no undo. Unpublishing is the reversible way to take something off a site.

Redirects cannot be managed one at a time. They travel inside a bundle on a clean-site import, or are handled at the CDN.

Generating a bundle from an existing website is not available. Bundles can be imported and exported, but the converter that turns a live site into one is not part of this interface.

Everything is loggedEvery action — including every refusal — is recorded with its time, the caller, the tool and the outcome. Deletions, publishes and clean-site imports are tagged so they can be found at a glance.
10

If something does not work

What you seeWhat it means
Tools do not appearThe configuration was not picked up. Restart the client, then check the URL and token for typos or trailing spaces.
401 UnauthorizedThe token is missing, mistyped, or has been rotated. Request a current one.
403 ForbiddenReached the service but from an unrecognised origin. A server-side setting — report it.
502 or no responseThe service is not currently running. Report it.
"no target was named"Two sites are configured and the request did not say which. Name akhil or client-b.
"Not connected to …"No session open for that site yet. Ask to connect to it first.
"needs a recent step up"Schema changes and clean-site imports need an elevated session. Ask to step up, then retry.
Entry URLs return 404The collection has no entry template, or it is still a draft. Check with connector_list_templates.
11

Handling the token

  • Treat it as a credentialAnyone holding it can read, edit, publish and delete on both sites. Store it where you would store a password.
  • Keep it out of shared placesNot in chat threads, tickets, screenshots or committed files.
  • Ask for a new one if exposedRotation is immediate and the old token stops working.
  • It is scoped to this serviceIt grants no access to anything beyond the two sites listed here.
