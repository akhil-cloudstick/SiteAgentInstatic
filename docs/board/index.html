R9 The proof chain: receipt, live verification, known-good, immutability Built 4 built

Depends on R7

Built 2026-09-21: the publish now says what it published. The content hash was computed to check If-Match and then discarded, and the deploy webhook carried no body, so nothing about WHAT went live ever reached the side that recorded the deploy — which is why a receipt could name a time and a URL and nothing else. Receipts are a new append-only table whose triggers refuse any later edit or delete, carrying the content identity, the page count, the Cloudflare project and deployment id, the verification result, the previous receipt, the retained bundle and the build that did it. "Live" is no longer a regex over the deploy tool’s output: the site is fetched afterwards and each sampled route must serve ITS OWN page, so a host answering its fallback under a 200 is caught — an HTTP-200 check is explicitly not sufficient. A check that cannot run reports "unverified", never success. The bundle that was uploaded is copied out after the deploy writes its root files, because the CMS keeps two generations and destroys the older one as the first step of the next publish, so there was no spare generation to point at. EXTENDED 2026-09-25: the live check no longer trusts a page title to prove a deploy. A title does not change between builds, so the one failure it could not see was the important one — an upload that silently does not land leaves the previous version serving, every title matches, and the deploy records as verified. Every page now carries a build stamp derived from its own bytes, written in immediately before upload, and the check compares that. It is per page, so a partial upload where some routes landed and others did not is caught route by route. Two further gaps found by the checking side are closed with it: the sampler checked at most twelve routes whatever the size of the site, and now checks every route up to sixty and says so when it samples above that; and where pages share a title, a fallback serving the wrong one used to pass, so a title that is not unique within a build is no longer used as a fingerprint and such routes are reported as indistinguishable rather than skipped in silence.
